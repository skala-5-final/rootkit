## 2. 서비스 소개와 기획 배경

**rootkit — 우리 회사 문서로 배우는 첫 실무**

rootkit은 회사의 기존 메일과 보고서를 학습 자료로 활용해, 신입사원이 업무 용어와 문서 작성 방식을 단계적으로 익히도록 돕는 AI 온보딩 학습 서비스다.

일반적인 영어 글쓰기 교육만으로는 회사마다 다른 업무 용어와 문서 관행을 익히기 어렵다. 회사 문서에 나타나는 표현을 맥락과 함께 이해하고, 직접 작성한 뒤 피드백을 반영해 수정하는 경험을 제공한다.

장기적으로는 용어 이해 → 문서 이해 → 부분 작성 → 전체 작성으로 확장할 수 있다. 다만 **현재 구현 단계는 그 네 가지를 각각 별도 화면으로 만드는 것이 아니라, 아래의 이메일 0·1·2단계**다. 보고서 작성은 확장 후보이며 이번 이메일 데모에 포함되지 않는다.

온보딩 학습 키트는 실제 업무를 연습하는 묶음이다. 향후 자료 요청, 일정 변경, 진행 상황 보고, 회의 결과 공유 등 업무별로 늘릴 수 있다.

## 3. 확정된 학습 흐름

### 0단계 — 빈칸 채우기

- 완성된 메일의 일부 표현을 빈칸으로 제공한다.
- 학습자는 문맥에 맞는 영어 표현을 채운다.
- 왼쪽: 업무 맥락, 빈칸이 있는 이메일 예시, 요구 사항.
- 오른쪽: 고정 제목과 빈칸이 있는 이메일 작성 영역.
- 제출 후 빈칸별 결과와 설명을 보고 수정·재제출한다.
- **현재 데모 선택:** 빈칸 3개, 드롭다운 선택형. 빈칸 수와 선택형/직접 입력 여부는 제품 전체에 고정된 요구 사항이 아니다.
- 예시: `Could you please`, `by`, `Please let me know`를 골라 자료 요청 메일 완성.

### 1단계 — 이메일 다듬기

- 왼쪽: 업무 맥락과 어색하거나 직접적인 표현으로 작성된 기본 영어 이메일.
- 오른쪽: 학습자가 직접 입력하는 제목과 본문.
- 기존 내용을 유지하면서 정중하고 명확한 비즈니스 이메일로 바꾼다.
- 현재 예시: 영업팀 Alex에게 이번 달 실적 자료를 금요일 오전 10시(KST)까지 요청.

### 2단계 — 상황별 작성

- 왼쪽: 업무 상황, 수신자, 필요한 사실과 요구 사항.
- **기본 이메일 원문은 제공하지 않는다.**
- 오른쪽: 제목과 본문을 직접 작성하는 에디터.
- 상황에 맞춰 문서의 구조와 문장을 스스로 구성한다.
- 현재 예시: 내부 일정 변경으로 Jamie와의 고객 미팅을 2026년 11월 4일 오후 2시에서 11월 5일 오후 3시(KST)로 변경 요청.

### 세 단계의 공통 규칙

- 문제 설명과 피드백은 한국어다. 학습용 이메일 원문·선택 표현·학습자 답안은 영어다.
- 제출은 **학습 답안 제출**이며 실제 이메일을 발송하지 않는다.
- 요구 사항과 참고 자료를 읽고 답안을 작성한다.
- 피드백을 확인한 뒤 수정·재제출할 수 있다.
- 같은 문제에 재제출할 때 문제와 평가 기준을 유지한다.
- 현재 데모는 원하는 단계에 바로 접근 가능하다. 단계 잠금이나 합격 점수는 결정하지 않았다.

## 5. 담당별 개발 범위

**왼쪽 화면을 AI 팀이 구현하는 것이 아니다. 좌우 화면 모두 Next.js 담당자가 구현하고, AI 팀은 화면에 표시할 문제 데이터를 제공한다.**

| 담당 | 책임 |
| --- | --- |
| Next.js 프론트 | 모든 화면, 단계 선택, 문제 표시, 빈칸 입력, 제목·본문 에디터, 제출·로딩·오류 상태, 평가 결과 표시, 수정·재제출, 기록 조회 |
| Next.js 서버 | 사용자 인증·권한, 사용자용 API, FastAPI 호출, 문제·답안·평가 결과 저장, 중복 제출 방지 |
| PostgreSQL / Drizzle | 사용자·문제·제출 기록과 평가 결과 보관, 데이터 관계·제약 관리 |
| FastAPI / AI | 단계별 문제 생성·제공, 사내 자료 검색(RAG), 정답·평가 기준 관리, 채점 및 한국어 피드백 생성 |
| 공동 협의 | 문제·평가 API 자료형, 오류 형식, 참고 자료 사용 범위, 지연 시간, 테스트용 응답 |

### 배점과 프론트의 관계

**배점 결정 및 계산은 프론트의 책임이 아니다.** AI/FastAPI가 평가 항목, 항목별 배점, 점수, 총점, 피드백을 반환하고 프론트는 이를 표시한다.

프론트에서 필요한 것은 배점 정책이 아니라 **응답 계약**이다. 예를 들어 항목 이름, 획득 점수, 만점, 설명을 배열로 받으면 항목 수나 배점이 바뀌어도 렌더링할 수 있다.

- 프론트에서 정답을 판단하거나 사용자 답안을 다시 채점하지 않는다.
- 총점·항목별 점수·만점은 서버 값을 사용한다. 표시용 비율만 계산할 수 있다.
- 입력 누락이나 길이 검증은 프론트와 서버가 수행하되, 학습 채점과 구분한다.
- **40/20/20/20점, 빈칸 40/30/30점, 총 100점은 기존 초안 또는 데모의 임시 값이다. 확정된 제품 정책이 아니다.**
- 현재 화면에는 `/100` 표시와 데모 배점이 있다. 실제 AI 연동 시 합의된 응답의 만점과 항목을 표시하도록 수정해야 한다.
- 점수 합격선, 단계 통과 여부, 다음 단계 잠금은 미결정이다.

## 6. 목표 시스템 구조와 데이터 흐름

```text
브라우저
   ↓ 단계 선택 / 답안 제출
Next.js 서버 ─── PostgreSQL
   ↓ 서버 간 인증
FastAPI / AI ─── 선정된 사내 문서·RAG 검색
```

목표 흐름:

1. 로그인한 사용자가 학습 단계 `0 | 1 | 2`를 선택한다.
2. Next.js 서버가 FastAPI에 문제를 요청한다.
3. FastAPI가 화면용 문제와 서버 전용 정답·평가 정보를 반환한다.
4. Next.js가 문제를 저장하고 화면용 데이터만 브라우저로 전달한다.
5. 브라우저는 문제 ID와 답안을 제출한다.
6. Next.js가 소유권 확인 후 저장된 문제·기준과 답안을 FastAPI에 전달한다.
7. FastAPI가 점수와 피드백을 반환한다.
8. Next.js가 결과를 저장하고 프론트에 전달한다.
9. 수정·재제출은 같은 문제의 새로운 제출 기록으로 추가한다.

정답, 채점 기준, 서버 간 토큰은 브라우저에 전달하지 않는다. 브라우저가 보낸 사용자 ID·문제 내용·배점을 신뢰하지 않고 서버 데이터로 확인한다.

## 7. AI 팀과 협의할 API 계약

아래는 **역할과 필수 데이터에 대한 초안**이다. FastAPI 구현 완료 또는 필드 확정을 의미하지 않는다.

### 문제 제공·생성

제안 경로: `POST /api/v1/exercises/generate`

- 요청: `stage` 필수, 업무 주제는 필요 시 추가.
- 공통 응답: 문제 ID, 단계, 제목, 한국어 상황 설명, 수신자, 요구 사항, 참고 자료.
- 0단계: 영어 본문 템플릿, 빈칸 ID, 빈칸별 선택지 또는 입력 규칙.
- 1단계: 개선 대상 영어 이메일 제목·본문.
- 2단계: 상황만 제공하며 원문 이메일은 없음.
- 서버 전용: 정답·평가 기준·기준 버전. Next.js 서버에서 보관하고 브라우저 응답에서는 제외.

### 답안 평가

제안 경로: `POST /api/v1/evaluations`

- 공통 요청: 제출 ID, 저장된 문제와 평가 맥락, 학습자 답안.
- 0단계 답안: 빈칸 ID별 선택 또는 입력 값.
- 1·2단계 답안: 영어 제목·본문.
- 공통 응답: 문제·제출 식별자, 총점과 만점, 항목별 점수와 만점, 한국어 요약·개선 피드백.
- 0단계: 빈칸별 정오와 설명.
- 1·2단계: 요구 사항 충족 여부, 고칠 부분, 이유, 영어 개선 표현.
- 참고 근거가 있으면 출처 ID를 제공. 없는 출처를 만들어내지 않는다.

합의해야 할 것은 JSON 필드명·자료형·선택 필드·오류 구조다. 세부 배점 정책은 AI 팀이 관리한다. 기존 예시는 `docs/rootkit-api-proposal.md`에 있으나, 그 문서의 1·2단계 한정 및 고정 배점 표는 최신 확정 사항으로 취급하지 않는다.

### RAG 사용 방향

담당자가 선정한 사내 문서를 학습 맥락과 피드백의 근거로 사용한다. 기존 문서의 모든 표현을 회사 공식 기준으로 단정하지 않는다. 승인된 예시와 작성 가이드를 구분하며, 실제 자료가 준비되기 전에는 가상·비식별 문서로 개발한다. 현재 UI에 표시하는 참고 자료는 가상 문구이며 실제 검색 결과가 아니다.

## 8. 현재 코드의 실제 상태

### 구현한 것

- Next.js App Router 기반 7개 주요 화면 경로.
- 0단계 빈칸 3개 선택, 1단계 메일 수정, 2단계 상황별 작성.
- 단계별 초안 자동 저장 및 다시 방문 시 복원.
- 표현 힌트와 가상 참고 문서.
- 제출 중 버튼·입력 비활성화, 요청 오류 안내.
- 채점 결과 표시, 답안 수정·재제출, 다음 단계 이동.
- 제출 답안·점수·피드백 이력과 제출 기준 진행률.
- 요청을 검증하는 데모 채점 Route Handler.
- `exercises.stage`가 0을 허용하도록 Drizzle 스키마 수정 및 증분 마이그레이션 생성.

### 데모에서만 사용하는 방식

- 로그인은 **닉네임 입력**이며 인증이 아니다. 학습 경로도 인증으로 보호하지 않는다.
- 문제는 `src/lib/learning.ts`의 고정 가상 데이터다.
- API는 `POST /api/demo/evaluations`이며 Next.js 서버에서 동작한다.
- 0단계는 서버의 정답 배열과 비교한다.
- 1·2단계는 키워드·구성·정중한 표현·분량으로 점수를 계산한다. 의미·문법을 평가하는 AI가 아니다.
- 저장소는 `localStorage`의 `rootkit-demo-v1`이며 닉네임·단계별 초안·최근 100개 제출을 보관한다.
- 공유 브라우저에서는 같은 데모 기록을 보며, `나가기`는 닉네임만 초기화한다.
- `submissions` 등 DB 테이블은 준비되어 있지만 **데모 화면은 DB에 학습 기록을 저장하지 않는다.**

### 아직 구현하지 않은 것

- 실제 회원가입·로그인·세션 및 사용자별 접근 권한.
- Next.js의 영속적인 문제·제출·평가 저장 API.
- 실제 FastAPI 호출과 AI 평가.
- 사내 문서 수집·검색 및 출처 연결.
- 비동기 작업·재시도 정책과 실운영 요청 제한.
- 최종 평가 응답 모델과 프론트 매핑.

`docker-compose.yml`에 AI 주소·토큰 환경변수가 있어도 실제 AI 호출이 구현됐다는 뜻은 아니다. DB 마이그레이션은 파일만 생성했으며 이 작업에서 실제 DB 적용 여부는 확인하지 않았다.

## 9. 현재 데모 API

`POST /api/demo/evaluations`

```json
{
  "stage": 0,
  "answer": {
    "subject": "Request for this month's sales report",
    "body": "",
    "blanks": ["Could you please", "by", "Please let me know"]
  }
}
```

- 단계: 정수 0, 1, 2.
- 제목 최대 200자, 본문 최대 10,000자. 이 제한은 현재 구현값이며 향후 협의 가능.
- 0단계: 빈칸 3개 모두 유효한 선택지여야 한다.
- 1·2단계: 공백을 제외한 제목·본문 필수.
- 성공 응답: `total`, `summary`, `scores`, `feedback`, `checks`, `mode: "demo"`.
- 입력 오류 422, JSON 파싱 오류 400. 클라이언트 요청 제한 시간 15초.
- 실제 FastAPI 계약과 동일한 API가 아니다. 연동 시 어댑터 또는 모델 변경이 필요하다.

## 10. DB 및 기술 구성

현재 `web/package.json` 기준: Next.js 16.4.2, React 19.3.0, TypeScript, Tailwind CSS 4, Drizzle ORM, postgres 드라이버. Docker 구성은 PostgreSQL 17을 사용한다.

| 테이블 | 현재 목적 |
| --- | --- |
| `users` | 사용자 ID, 이메일, 이름 |
| `exercises` | 사용자별 단계·주제·문제 JSON·서버 전용 채점 JSON |
| `submissions` | 문제별 제출 제목·본문, 상태, 평가 JSON, 총점, 제출 시각 |

- 단계 CHECK 제약: `0, 1, 2`.
- 제출 상태: `pending`, `evaluating`, `completed`, `failed`.
- 동일 문제·클라이언트 요청 ID의 중복을 막는 유니크 제약이 있다. 실제 API의 중복 요청 처리 로직은 아직 필요하다.
- 마이그레이션: `web/drizzle/0001_secret_hobgoblin.sql`.
- 0단계 답안의 영속 저장 구조는 미확정이다. 빈칸 ID별 응답 JSON을 별도 저장할지 합의해야 한다. 채점 전에 답안 자체가 저장될 수 있어야 한다.
- 원문 문서와 검색 인덱스 관리 방식은 AI 팀과 결정한다.

## 12. 실행 및 검증 이력

### 데모 실행

저장소 루트에서:

```bash
cd web
pnpm install  # 의존성이 없는 경우
pnpm dev
```

접속: `http://localhost:3000`. 데모 화면은 DB와 FastAPI 없이 실행할 수 있다. 이전 세션의 서버 프로세스가 살아 있다고 가정하지 않는다. 예전 `http://127.0.0.1:8765`는 정적 HTML 미리보기이므로 Next.js 화면 확인에 사용하지 않는다.

### DB를 포함한 실행

루트의 `README.md`와 `docker-compose.yml` 참고. 로컬 개발은 DB 실행 및 환경변수 설정 후 `pnpm db:migrate`를 사용한다. DB 변경은 기존 마이그레이션을 덮어쓰지 않고 증분으로 생성한다.

### 2026-10-22 확인한 내용

- TypeScript 타입 검사 통과.
- `pnpm build` 프로덕션 빌드 통과.
- 주요 화면 경로 7개 응답 확인.
- 0단계 정답 100점·오답 0점, 1·2단계 정상 예시 채점 확인.
- 잘못된 단계, 빈 본문, 제목 길이 초과 검증 확인.
- 브라우저에서 스플래시 → 데모 시작 → 키트 → 0·1단계 제출 → 기록 조회 확인.
- 새로고침 후 제출 기록 유지 확인.
- 실제 인증, FastAPI, DB 기록 저장, 마이그레이션 적용 검증은 수행하지 않음.

작업 환경에서 Turbopack 내부 포트 권한 오류가 있었다. 권한을 허용하고 실패가 저장된 빌드 캐시를 분리한 뒤 성공했다. 앱 오류와 실행 환경 제약을 구분한다. Next.js의 캐시·프리렌더 설정에 맞춰 학습 경로에 정적 파라미터와 로딩 경계를 추가했다.

## 13. 다음 개발 순서 제안

1. **AI API 계약 확정:** 0·1·2 문제 데이터, 빈칸 답안 구조, 평가 결과·만점·오류 형식 합의. 프론트용 고정 응답부터 공유.
2. **인증 방식 결정 및 구현:** 실제 사용자 세션, 문제·답안 소유권 확인. 닉네임 데모와 분리.
3. **DB 저장 연결:** 문제·제출·결과 저장, 기록 조회, 0단계 답안 저장 모델 확정.
4. **FastAPI 연결:** Next.js 서버에서 호출, 임시 채점 함수 교체, API 결과를 화면 모델에 매핑.
5. **실패 처리:** 지연·중복 제출·재시도, 실패한 평가를 0점으로 표시하지 않기, 입력 보존.
6. **RAG 연동:** 선정된 문서, 출처 표시, 문제와 평가 기준의 일관성 확인.
7. **통합 확인:** 사용자별 기록 분리, 세 단계 제출, 수정·재제출, 서버 장애 흐름 검증.

이는 권장 순서이며 구현 완료를 의미하지 않는다.

## 14. 미결정 사항과 범위 밖 기능

### 아직 합의가 필요한 항목

- 실제 인증 방식 및 가입 정책.
- FastAPI의 최종 필드명·버전·인증·응답 제한 시간.
- 점수 체계, 평가 항목, 합격 기준. **AI 팀 책임으로 논의하며 프론트에 정책을 고정하지 않는다.**
- 0단계 선택형 유지 여부, 빈칸 수, 문제별 배점, 저장 모델.
- 주제별 문제 수, 난이도, 문제 새로 생성 및 재학습 방식.
- 단계 잠금, 통과 기준, 키트 완료의 정의. 현재 완료 표시는 단순 제출 여부다.
- 실제 사내 문서 확보·승인 및 검색 인덱스 구성.
- 동기 평가로 시작할지, 작업 ID 기반 비동기 평가가 필요한지.

### 현재 우선 범위에서 제외

실제 이메일 발송, 보고서 작성 과정, 첨부 파일·리치 텍스트 에디터, 관리자 문서 업로드 화면, 다중 회사 조직 관리, 고급 통계 대시보드, 스트리밍 채점.

## 15. 다음 세션 작업 원칙

- 이름은 rootkit, 총 3단계이며 코드 값은 0·1·2, 문제 설명·피드백은 한국어, 답안은 영어라는 결정을 유지한다.
- 기존 HTML을 다시 만드는 대신 `web/`의 Next.js 앱을 수정한다.
- `web/AGENTS.md`와 설치된 Next.js 문서를 먼저 확인한다. 이 프로젝트는 캐시·프리렌더 기능을 사용한다.
- 사용자 요청이 없으면 데모를 실제 인증·AI 연동이 완료된 서비스로 설명하지 않는다.
- 고정 배점과 데모 키워드 채점을 확정된 제품 정책으로 취급하지 않는다.
- 새 결정이나 구현 변경 시 이 문서의 상태·미결정 항목도 함께 갱신한다.

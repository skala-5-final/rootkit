- 명시된 수신자 그룹·언어·상황, 3개 독립 사례, 보고서·복제·서로 충돌하는 구성 패턴 제외.

- 문제 표시 시점 스냅샷, B 활성화 후 A의 첫 제출·재제출, 서버 재시작 후 저장 결과 재사용.
- 동일 요청의 동시 재시도에서 모델 호출 한 번, 변경 답안의 409, 모델 실패 후에도 요청 ID와 답안의 결합 유지.
- 만족한 조건에는 결함을 출력하지 않음, 구체적 피드백 의미 검토, 날짜·수량·상태 수정 예시의 별도 사실 검토와 누락 검토 거절.
- 검토 실패한 문제의 출제 제외, 키·모델 설정 누락, 모델/응답 오류의 성공 대체 차단, 외부 API 리디렉션 거절.
- 내부 Bearer 인증, 사용자 소유권, 브라우저의 사용자 ID·기준·승인 필드 차단, 학습자 응답에서 내부 기준 제거.
- CLI 반입·추가·교체·용어 승인·검토 내보내기와 실패 기록.

## 실제 HTTP 경계

최종 Next.js 프로덕션 빌드를 `127.0.0.1:3001`, 테스트 전용 FastAPI를 `127.0.0.1:8001`에서 실행했다. 기존 PostgreSQL 로그인 계정으로 인증하고, RAG 데이터는 `/private/tmp/rootkit-browser-ai.xITlLR/browser.sqlite3`에 격리했다. FastAPI 모델은 외부 호출이 없는 테스트 전용 응답이다.

실제 Next.js→FastAPI 네트워크 검사 **12개 통과**:

1. 미인증 Next 요청 401.
2. 미인증 내부 FastAPI 요청 401.
3. 다른 Origin의 요청 403.
4. 브라우저가 사용자 ID를 추가한 요청 422.
5. 다른 사용자 시도 접근 404.
6. A 출제 응답에서 기준·검토 정보 비노출 및 저장된 시도 생성.
7. B 활성화 뒤 A 첫 평가가 A 날짜를 사용.
8. 동일 요청 재시도가 저장된 결과를 반환.
9. 같은 요청 ID의 다른 답안은 409.
10. 수정한 A 답안은 새로운 요청으로 평가되어 `match`, 결함 피드백 없음.
11. 새 시도는 B의 문제와 날짜를 사용.
12. 기록에 A의 제출·재제출 2건이 보존됨.

## 검증 중 수정한 문제

- 저장소의 `pnpm@11.13.0`을 패키지 매니저가 손상된 배포판으로 거절했다. 실행 가능한 같은 주 버전 `11.15.1`로 변경하고 의존성을 설치했다.
- 최초 Turbopack 빌드가 샌드박스의 로컬 포트 제한으로 실패했다. 실패한 생성 캐시를 임시 폴더로 보존하고 허용된 실행 환경에서 최종 빌드를 통과시켰다.
- 실제 브라우저 요청에서 Next.js의 내부 `localhost` 주소와 브라우저 `127.0.0.1` 주소 차이 때문에 정상 요청이 CSRF 검사에 막혔다. 실제 Host를 사용하도록 수정하고 다른 Origin·위조 forwarded host·포트 없는 Host 회귀 테스트를 추가했다.

## 최초 구현 이후 실제 재평가 개선

2026-10-23 후속 작업. 모델 키 설정과 더미 문제집 활성화 이후 실제 사용에서 반복 보류가 발생해 추가 확인했다. 위 최초 검증은 모의 응답을 사용한 기록이며, 아래는 별도의 실제 모델 검증이다.

확인한 원인은 완료된 요청 ID를 계속 재사용하던 웹 처리, 답안의 오류와 AI 피드백의 오류를 혼동하던 검토, 개별 검토와 전체 판정의 불일치였다. `gpt-4.1-mini` 평가와 `gpt-5.4-mini`의 낮은 추론 설정에서도 과잉 지적·작성 지시문 오인·잘못된 지적 통과 사례가 관측되어, 모델 이름 변경만으로 해결됐다고 판단하지 않았다.

최종 원칙 버전은 `2026-10-23.7`이다. 평가 생성은 `gpt-5.4-mini`의 `medium`, 독립 의미·사실 검토는 같은 모델의 `high`를 별도 요청으로 사용한다. 의미 검토가 답안의 실제 구절과 조건 판단을 먼저 작성하도록 하고, 답안에 없는 인용은 거절한다. 한국어 출력 및 그대로 사용할 수 있는 수정 문장을 요청한다. 시간 제한·재시도·자동 개선 범위는 [운영 설정](./rag-feedback.md)에 기록했다.

최종 코드 검증:

- Python 단위·통합 테스트 **76개 통과**. 역할별 모델·추론 설정, 제한된 재시도와 전체 시간 예산, 개선 후 재검토, 계속 실패하면 보류, 인용 검증과 감사 기록, 일반 조언 접두 중복 방지 포함.
- 웹 회귀 테스트 **24개 통과**. 실제 제출 헬퍼의 타임아웃→같은 요청 복구→완료 후 새 ID, 응답 ID 불일치, 이전 버전의 완료 요청 복구 포함.
- TypeScript와 변경 파일 ESLint 통과. 웹 프로덕션 Docker 빌드 및 최종 AI Docker 빌드 통과.
- Docker 웹·AI를 재생성해 적용했다. PostgreSQL과 AI 데이터 볼륨, 기존 시도·제출 이력은 유지했다.

Chrome의 실제 사용 중인 시도 `d054fbe0-1308-44e9-810a-a30bf9ab5642`에서 답안을 바꾸지 않고 `다시 평가하기`를 눌렀다. 새 요청 `f5c3b6c5-e953-4036-825a-80421b0f08ee`가 생성되어 한국어 **수정 필요**로 저장됐다. 기존 결과는 덮어쓰지 않았다. 답안에 있는 사실·기한은 인정하고, 작성 지시문 형태의 정중한 요청·일정 조율 부분에만 피드백을 표시했다. 실제 수정 예시는 다음과 같다.

> 자료를 2026년 11월 6일 10:00 KST까지 이메일로 보내주시면 감사하겠습니다. 기한 내 전달이 어려우시면 가능한 전달 시점을 알려주시기 바랍니다.

감사 기록에서 실제 모델 요청 3회(평가·의미 검토·사실 검토), 모든 검토 통과, 원칙 버전 `.7`을 확인했다. 브라우저 오류 로그는 빈 배열이었다. 화면 증빙은 `/tmp/rootkit-reevaluation-fixed.png`다.

운영 SQLite에서 기존 답안 4개의 고정 스냅샷을 읽어 별도 임시 SQLite에 복제하고, 정답과 날짜 오류 대조 사례를 추가했다. 기존 제출 이력은 바꾸지 않았다. 최종 실제 모델 결과 **6개 모두 기대 상태와 일치**했다.

| 실제 입력 | 확인한 결과 |
| --- | --- |
| 수령 상태를 잘못 쓴 매우 짧은 답안 | `needs_revision`: 요청 사실·기한·정중한 요청 및 조율 보완 |
| 기한과 일정 조율이 없는 초안 | `needs_revision`: 누락된 기한·일정 조율 피드백 |
| 11월 7일로 잘못 쓴 답안 | `needs_revision`: 올바른 기한과 누락된 일정 조율 문장 제시 |
| 요구사항을 그대로 복사한 답안 | `needs_revision`: 이미 있는 사실·기한은 인정, 실제 정중한 요청·조율 문장 제시 |
| 완성된 올바른 메일 | `match`, 결함 피드백 없음 |
| 올바른 메일에서 기한만 하루 늦춘 답안 | `needs_revision`, 기한 기준만 적용하고 11월 6일 10:00 KST로 수정 |

여섯 결과의 요약·피드백은 모두 한국어였고, 각 결과를 같은 요청 ID로 다시 조회했을 때 모델 평가 이벤트가 추가되지 않았다. 이번 표본에서는 모두 1회 생성 및 별도 검토 2회로 확정됐고, 처리 시간은 약 14~57초였다. 이는 해당 호출에서 관측한 시간이며 성능 보장은 아니다. 결과는 `/private/tmp/rootkit-reevaluation-final-results.json`에 남겼다.

추가 표현 다양성 사례에서는 올바른 메일의 ‘보내주실 수 있을까요?’를 ‘보내주세요.’로, 일정 조율 표현을 ‘알려주시면 감사하겠습니다.’로 바꿨다. 같은 사실과 목적을 유지한 이 답안은 자동 개선 1회를 거쳐 `match`로 확정됐고 결함 피드백은 없었다. 총 7개 실제 답안 사례를 확인했으며, 추가 결과는 `/private/tmp/rootkit-paraphrase-final-results.json`에 보관했다.

추가로 의도적으로 잘못 만든 피드백을 임시 테스트에만 주입하고 **실제 검토 모델**에 보냈다. 이미 올바른 기한이 있는 답안에 대한 ‘기한 누락’ 지적은 의미 검토에서 거절했다. 같은 답안에 11월 8일로 고치라는 제안은 의미 검토와 사실 검토 모두 거절했다. 생성 결과를 대체한 이 2개 음성 사례는 실제 피드백 생성 정확도 검증과 구분한다.

## 아직 검증하지 않은 부분

- 다양한 한국어·영어 업무 유형에 대한 대규모 의미 정확도. 위 실제 모델 표본은 전체 정확도를 보장하지 않는다.
- 실제 회사 자료에 대한 추출·생성·검토 품질. A/B는 가상의 테스트 자료다.
- 대규모 자료·다수 동시 사용자의 부하, 운영 환경의 HTTPS 프록시, 배포 환경 검증.

SQLite 평가 직렬 처리, 모델 컨텍스트 크기 제한, JSONL만 지원하는 범위는 [운영 안내](./rag-feedback.md)에 명시했다. 테스트 결과는 제어 흐름과 경계 처리에 대한 근거이며 실제 AI 정확도 점수가 아니다.
